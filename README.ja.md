# Evidence-Driven Agent Workflow

[中文](README.md) · [English](README.en.md) · **日本語**

AIに任せる開発を、明確な目標、範囲を限定した実行、検証可能な成果につなげるスキルです。

機能実装、バグ調査、性能改善、AGENTS.mdやスキルの効果を調べる比較実験に使います。目標を定義し、既存のプロジェクトを観察し、限られた実験を行い、実際の動作を検証してから根拠とともに報告します。小さく可逆的な変更には短い手順を使い、複雑な計画を強制しません。

## 着想と出典

Thorsten Ballの [How I work with Agents](https://x.com/thorstenball/status/2114386050638336082) に着想を得ています。独自に記述した手順であり、全文翻訳でも、著者やAmpの公式スキルでもありません。

成果から考えること、ツールによる観察、まとめて比較する反復、根拠に基づく検証、影響範囲に応じたレビューを取り入れました。「常に最新モデルを使う」「大半のコードをレビューしない」「自動で本番に公開して顧客へ連絡する」は無条件の命令にしていません。[出典との対応表](references/source-mapping.md) に15項目の扱いと追加の制約を示しています。

**スキルはタスク中に指示を読み込む仕組みです。モデルの重みを学習・更新するものではなく、永続的な記憶や性能向上を保証しません。** 効果は実際の比較実験で確認する必要があります。

## 主な機能

- 曖昧な要望を観察可能な受け入れ条件に変え、指定済みの技術や制約を維持する。
- 実際のコード、テスト、ログ、画面の動作を根拠に判断する。
- 仮説と実験の数を限定し、無制限の再試行を避ける。並列実行前にファイルや資源の分離を確認する。
- 画面表示、操作、本番・永続化状態、性能の根拠を区別する。
- 重大な影響がある変更に人のレビューを優先しつつ、必要なテストや既存のレビュールールを維持する。
- 新しいコンテキストで対照群と処置群を比較し、条件の混入や少数サンプルの限界を報告する。

## 使い方

ディレクトリ形式のAgent Skillsに対応したクライアントへ標準パッケージを取り込むか、そのクライアントが指定するスキル用ディレクトリへ配置してください。WorkBuddyのユーザー用配置先は `~/.workbuddy/skills/evidence-driven-agent-workflow/` です。ローカル用プロファイルには作成マーカーが付いています。他のクライアントでは各製品の説明に従ってください。

依頼例：

> evidence-driven-agent-workflowで、このパーサーの空文字列チェックを修正してください。APIは維持し、公開はせず、実際の回帰テスト結果を示してください。

> この検索APIを改善してください。最初に現状の遅延を測定し、認可とレスポンス形式を維持してください。目標に届かなくても実測結果を報告してください。

> このAGENTS.mdによって、修正前に不具合を再現する行動が増えるか評価してください。実行予算を確認し、分離した条件で比較してください。

変更ファイル、実行した検証、観測結果、未検証の経路、残るリスク、必要な承認を報告します。これらは期待する動作の例であり、実施済みのテスト結果ではありません。

## 配布形式

| ファイル | 用途 | メタデータ |
| --- | --- | --- |
| `evidence-driven-agent-workflow.zip` | 汎用Agent Skillsクライアント | 標準フィールド。バージョンと作成マーカーはmetadata内に保存 |
| `evidence-driven-agent-workflow-skillhub.zip` | SkillHubのWebアップロード | トップレベルにslug、displayName、version、summary、作成マーカーを追加。SKILL.mdはZIP直下 |

本文と参照資料は共通です。標準作成ツールのパッケージャーはスキルの親ディレクトリを残します。SkillHub用ZIPでは外側のディレクトリを除きます。**プラットフォーム固有の拡張フィールドを、厳密な汎用標準として扱わないでください。**

SkillHub用の情報：

- Slug：`ninetyhe-evidence-driven-agent-workflow`
- 表示名：`证据驱动的 Agent 工程工作流`
- バージョン：`1.0.0`
- 説明：目標、限定した実験、実際の検証、影響範囲に応じたレビューによる開発支援。
- アップロード：https://skillhub.cn/dashboard/publish

確認したWeb画面の上限は200ファイル、合計10MBです。パッケージはテキストのみで、入れ子の圧縮ファイル、実行スクリプト、認証情報、原記事の画像を含みません。Slugの利用可否と審査結果はプラットフォームが決定します。

現在インストールされているSkillHub CLI 2026.3.7にはpublishコマンドがありません。プラットフォームのdry-runは未実行で、自動更新もしていません。Web用ZIPを使うか、[公式CLIガイド](https://skillhub.cn/tutorials#publish-via-cli) に従い、公開に対応したバージョンを準備してください。今回行うのはパッケージの作成のみで、審査への提出や公開は行いません。

## 権限と評価上の制限

固定モデル、APIキー、クラウドサービス、実行スクリプトは不要です。実際の開発にはホスト側のファイル・テストツールが必要です。実行環境がなければ分析のみを行い、検証できていない事項を明記します。無断でソフトをインストールし、課金し、公開し、メッセージを送信し、定期ジョブを作成することはありません。サンドボックスは業務操作の権限を与えません。

形式検証や例のレビューだけでは開発成功率の向上は証明できません。[10件の受け入れ例](references/acceptance-examples.md) で確認し、代表的なタスクについて [比較評価](references/knowledge-evaluation.md) を行ってください。
